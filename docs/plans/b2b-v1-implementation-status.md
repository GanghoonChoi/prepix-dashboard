## 2026-10-06 공통 기반과 프로젝트 묶음

백엔드에 `b2b_teams`, 참여 속성, 프로젝트, 참여자, 중복 요청 기록, 감사와 outbox를 추가했다. 마이그레이션 0043은 기존 팀을 자동 전환하거나 이용 종료일을 만들지 않는다. 신규 팀 적용은 `B2B_ENABLED=true`와 `B2B_NEW_TEAMS_ENABLED=true`가 모두 있어야 하며 기본값은 false다. 기존 팀의 명시적 소유자 전환은 기존 공유 보관함 범위를 기록하고 첫 이용기간을 지급하지 않는다.

프로젝트 생성·목록·검색·개요 수정·참여 범위·담당자 이전을 구현했다. 소유자, 관리자, 결제 담당자도 프로젝트 참여가 없으면 목록·검색·직접 조회에서 내용을 볼 수 없다. 현재 계정과 팀·프로젝트 접근을 중복 요청의 저장된 결과를 반환하기 전에도 재검사한다. revision과 팀 행 잠금으로 동시 수정과 배정을 직렬화하고 업무·감사·outbox를 함께 확정한다.

팀 참여에는 기존 프리뷰 정원을 적용하지 않는다. 웹 제작자 역할과 다운로드 허용을 팀 역할에서 분리했다. 멤버 삭제·정지 시 DB 트리거가 프로젝트 참여와 결제 위임을 회수해 이전 API나 관리 작업으로 제거한 뒤 재참여해도 과거 권한이 살아나지 않게 했다. 외부 참여자를 관리자·소유자로 승격하는 경로와 B2B 팀에 대한 기존 조직 관리 API를 차단했다. 신규 프로젝트 자료는 기존 공간 전체 보관함 API를 이용하지 않는다.

대시보드에 프로젝트 목록·생성·개요·참여자와 이용 상태 화면, 상태별 메뉴·팀 홈을 연결했다. 생성 응답이 유실되면 같은 내용과 요청 식별자로 다시 확인하고 입력을 유지한다. 수정 충돌 시 현재 내용과 사용자 입력을 함께 보존한다. 접근 거절 시 제목·개요를 제거한다. 팀 플랜은 현재 판매 미개방 상태를 표시하며 개인 프리뷰 제공량을 B2B 제공량으로 표시하지 않는다. 로그인·가입 전환 링크의 초기 렌더링 차이도 수정했다.

서버의 `backend/src/b2b/contracts.ts`가 클라이언트 계약의 기준이다. 대시보드의 `node scripts/sync-b2b-contract.mjs`로 생성하고 `--check`로 차이를 검사한다. 시각은 ISO 값으로 응답하고 한국 시간으로 표시한다. 기간 종료 시각은 제외하며 E, E+30일, E+60일의 정확한 경계를 검증했다.

## 2026-10-06 범위별 초대와 무료 참여 동의

팀 내부 참여 초대와 프로젝트 내부/외부 초대를 별도 범위로 구현했다. 신규 참여는 이메일을 증명한 로그인 계정이 명시적으로 수락해야 확정되며, 프로젝트 역할 변경 API로 신규 참여나 과거 권한을 되살릴 수 없다. 프로젝트 담당자는 외부 참여자를 자신의 프로젝트에 초대할 수 있고, 새 내부 직원 추가에는 팀 관리 권한이 필요하다. 외부 참여자는 직원 조직이나 기존 공간 전체 보관함에 자동 편입되지 않는다. 초대는 이용권·AI를 지급하지 않는다.

7일 초대, 취소·재전송 사유와 revision, 세대 변경으로 이전 링크 무효화, 현재 발행자 권한 재검사, 계정 이메일 불일치 시 내용 비공개와 마스킹 안내를 연결했다. 해시와 키 버전만 저장하며 비밀 링크는 버전별 키에서 발송 시 재구성한다. 구성 누락 시 초대를 발행하지 않는다. 영속 메일 대기열은 잠금·발송 lease·원발송 단위 중복 방지와 24시간 재시도를 사용한다. 최초 발송 내용은 보존하므로 팀명이나 가입 상태가 바뀌어도 같은 메일 재시도의 내용이 바뀌지 않는다.

대시보드에서 초대 범위·역할·다운로드 권한·만료를 확인하고 수락할 수 있다. 팀 관리자 명단에서 내부와 외부를 나눠 표시하고, 소유자에게 참여 구분과 결제 위임 변경을 연결했다. 응답 유실 시 같은 요청과 입력을 재사용하며 재전송·취소와 결제 위임에 중복 변경을 만들지 않는다. 참여 구분 변경은 직원 조직과 함께 반영하고 이전 구분의 대기 초대를 취소한다.

확인: 백엔드 빌드, B2B PostgreSQL·정책 검사 20개, 기존 공간·조직·자료·인증·메일 159개, 대시보드 단위 검사 89개·타입·변경 코드 lint·계약 동기화·빌드가 통과했다. 브라우저 2개가 준비 상태·프로젝트 비공개·담당자 이전·즉시 회수와 외부 초대·이메일 증명·검토자 범위·응답 유실 결제 위임을 확인했다. 실제 메일 대신 로컬 포착함만 사용했다.

## 2026-10-06 참여 종료와 객관적 담당자 복구

팀 역할·정지·재활성화·제거를 사유와 대상 revision으로 변경하고 감사/outbox와 함께 확정한다. 관리자 승격·관리자 변경은 소유자만 가능하고 외부 참여자나 마지막 소유자를 승격·제거할 수 없다. 즉시 정지·제거는 후임 지정이나 자료 인계를 기다리지 않고 프로젝트·결제 권한을 회수하며 기존 진행 중 전송과 소유권 이전 대기도 취소한다. 재활성화는 참여만 복구하며 과거 프로젝트 접근을 재생하지 않는다. 신규 이용권/AI와 구매 감액·환불은 발생하지 않는다.

자발적 탈퇴는 사유와 revision을 받으며 본인에게만 탈퇴 확인 응답을 중복 반환한다. 소유자는 후임이 이전을 수락하기 전 탈퇴할 수 없다. 담당자가 공석이거나 참여/계정이 중지된 경우에만 소유자가 이미 수락한 내부 참여자를 후임으로 지정한다. 복구 화면은 전달받은 특정 프로젝트 주소에서 최소 운영 정보와 지정 가능한 참여자를 확인하고 제목·개요·파일을 반환하지 않으며 소유자에게 참여를 새로 부여하지 않는다.

B2B로 전환한 팀은 기존 역할/탈퇴/초대 API로 새 사유·동의 정책을 우회하지 못한다. 기능 플래그를 꺼도 전환된 팀의 외부 참여자 보관함 제한과 내부 후임 조건을 유지한다. 기존 공유 보관함도 E부터 쓰기를 차단하고 E+30일부터 자료 조회를 차단한다. 서명 키가 누락된 오래된 초대는 개별 발송 실패로 처리하여 다른 초대를 막지 않는다.

검증: B2B PostgreSQL·정책 24개와 기존 검사 159개 통과. 서비스·대시보드 빌드, 대시보드 타입·변경 코드 lint·계약 동기화 통과. 브라우저에서 기존 비공개 프로젝트 흐름 1개, 외부 초대/결제 위임 응답 유실/정지/재활성화/탈퇴 1개, 소유자 자료 접근 없이 담당자 복구 1개를 확인했다. 소유권 이전의 B2B 사유·revision·결제 위임 회수 이력 보강은 다음 작업이며, 이후 이용권과 새 자료 도메인의 참여 종료 처리를 같은 회수 흐름에 연결해야 한다.

## 2026-10-06 소유권 수락과 결제 위임 회수

B2B 소유권 요청·수락·취소·거절은 사유, 팀 revision과 요청 식별자를 받고 업무·감사·outbox를 함께 확정한다. 요청과 수락에는 기존 비밀번호/연결된 Google 계정의 5분 단회 본인 확인을 재사용한다. 내부 참여자만 후임이 될 수 있으며 현재 소유자·수락자의 접근을 다시 검사한다. 입력 해시에서 재확인 자격 증명을 제외하여 응답 유실 뒤 새 본인 확인으로 같은 요청 결과를 확인할 수 있다. 암호·Google 토큰·원 nonce는 중복 요청 기록이나 감사에 저장하지 않는다.

수락하면 이전 소유자를 관리자로 바꾸고 이전 결제 위임을 회수하며 새 소유자와 직원 조직 역할을 같은 거래에서 확정한다. 이용기간·구매 정원·AI 원장은 바꾸지 않는다. 기존 소유자는 후임이 수락한 후 탈퇴할 수 있다. 이전 관리 API로 B2B 소유권 절차를 우회하지 못한다. 일반 참여자의 기존 팀 조회는 본인 명단만 반환하며 직원 목록과 기존 프리뷰 정원을 노출하지 않는다. 권한 변경 후 현재 공간 정보를 갱신하면서 처리 결과 미확인 요청의 대상과 내용을 유지한다.

검증: 서비스 빌드, B2B PostgreSQL·정책 25개, 기존 검사 159개, 대시보드 빌드·타입·변경 코드 lint·계약 검사 통과. 요청/수락 동시 중복, 취소/거절, 이전 결제 회수와 이용기간 보존을 확인했다. 브라우저에서 요청·수락 응답 유실과 서버 상태 재조회 뒤 재확인, 후임 수락 후 기존 소유자 탈퇴를 확인했다. 앞의 프로젝트·외부 참여·담당자 복구 브라우저 흐름도 통과했다.

## 2026-10-06 신규 팀 생성 요청과 준비 상태 온보딩

팀 생성에 계정별 요청 식별자와 영속 결과 기록을 추가했다. 같은 요청의 동시 처리와 응답 유실 후 재시도는 동일한 팀과 확인 응답을 반환하고, 이름이 같더라도 식별자가 다른 요청은 별도 팀을 만든다. 생성 가능 횟수를 소진하거나 신규 적용 플래그를 되돌린 뒤에도 이미 생성한 요청을 확인할 수 있다. 현재 계정·참여·삭제 상태를 저장된 응답보다 먼저 검사하므로 제거된 참여나 삭제 중인 팀을 재시도로 되살리지 않는다.

B2B 팀명과 정보 수정은 1~100자 계약을 사용하며 기존 팀은 80자 계약을 유지한다. 마이그레이션 0046은 이름 열을 확장하고 생성 요청 기록만 추가한다. 신규 B2B 생성은 준비 상태·내부 소유자·초기 결제 권한, 업무 감사와 outbox를 같은 거래에서 확정하며 이용기간이나 체험·AI를 지급하지 않는다. 감사/outbox 실패 시 팀·조직·요청 기록도 함께 취소된다. 요청 식별자가 없는 기존 클라이언트는 신규 B2B 적용이 꺼져 있을 때 기존 이름 기준 재시도 동작을 유지한다. 서버는 요청 식별자 지원 여부를 capabilities에 명시하며 새 대시보드는 이 필드가 없는 구버전 서버에 기존 생성 입력만 보낸다.

대시보드의 팀 생성과 첫 실행 화면은 결과 미확인 시 원래 입력·식별자를 유지하고 입력과 취소를 잠근다. 이미 생성된 팀의 다음 화면 조회만 실패한 경우에는 새 생성 요청 없이 그 팀으로 다시 이동한다. 신규 B2B 안내에는 프리뷰 정원을 표시하지 않고 첫 구매 반영 전 준비 상태를 설명한다. 첫 실행의 기존 초대 폼과 보관함 연결을 B2B에 제공하지 않으며, 팀 홈에서 현재 이용 상태와 설정·구매를 이어 확인한다. 준비 상태에서는 참여 관리와 프로젝트 업무가 계속 차단된다.

검증: 서비스 빌드, B2B PostgreSQL·정책 31개, 기존 공간·조직·자료·인증·메일 159개, 대시보드 단위 검사 89개와 타입·변경 코드 lint·계약 검사·빌드 통과. 신규 생성·호환 브라우저 3개가 응답 유실·100자·동일 이름의 별도 생성·생성 후 이동 실패 재시도·준비 상태 유지·구버전 서버 입력 호환을 확인했다. 기존 B2B와 온보딩 브라우저 10개도 모두 통과했다. 신규 적용 브라우저는 로컬 harness의 `B2B_TEST_NEW_TEAMS=true`만 사용했으며 운영 플래그는 변경하지 않았다.

## 2026-10-06 상품 조건과 영속 구매 견적

팀 상품을 명시적 설정으로 읽고 가격·편집 정원·AI 단위·저장/전송 제공량·추가 팩 유효기간·반올림·견적/주문 유효시간·환불 정책 버전을 모두 요구한다. 설정 누락을 무료나 무제한으로 해석하지 않는다. 마이그레이션 0047은 상품 조건 버전, 구매 기간과 견적을 추가하며 기존 프리뷰나 팀 종료일에서 구매를 추정하지 않는다. 상품 조건과 견적은 DB에서 불변으로 보존하고 같은 버전의 조건 변경을 거절한다.

검증: 서비스 빌드, B2B 정책·PostgreSQL 검사 41개, 기존 공간·조직·자료·인증·메일 검사 159개 통과. 대시보드 단위 검사 89개·타입·변경 코드 lint·계약 동기화·빌드 통과. 구매 브라우저 검사에서 응답 유실 후 같은 견적 확인, 입력 잠금, 공급가액/부가세/제공량, 조건 보존과 견적 후 E 미지급을 확인했다. 로컬 가짜 상품 fixture만 사용했고 운영 판매 조건은 설정하지 않았다. 전체 백엔드 테스트 포함 타입 검사의 기존 오류 3건은 앞의 기준선과 같다.

## 2026-10-06 원주문과 수납 재대조 기반

마이그레이션 0048에 팀 원주문·결제 시도·확인된 수납·복구 결제 안전 기록을 추가했다. 주문에는 견적과 구매자 사본, 상품 조건, 대상 기간과 금액을 보존하고 DB에서 수정하지 못한다. 같은 견적을 두 주문으로 만들지 않으며 결과 미확인·수납 미적용·운영 확인 주문이 있으면 새 결제를 막는다. 주문 생성과 결제 확인에도 현재 팀 참여·결제 권한을 먼저 검사한다.

## 2026-10-06 수납의 구매 기간과 제공량 반영

## 2026-10-06 사용자 이용권과 장치 허가의 서버 기반

마이그레이션 0050에 기간별 사용자 배정, 개인 AI 한도, 장치 공개키·단회 확인 요청·서명 허가를 추가했다. 실제 수납 적용이 있는 구매 기간과 수락한 참여자에게만 배정하며 활성·미래 예정·회수 대기를 구매 정원에 포함한다. 개인 한도는 독립 revision과 확정 사용+예약 하한을 사용하며 재배정으로 사용 이력·한도·공동 AI 지급을 초기화하지 않는다.

회수는 새 서버 행동을 즉시 막고 기존 모든 장치가 허가를 영속 반납하거나 원래 만료에 도달할 때까지 정원을 유지한다. 서버의 회수 요청과 장치의 확인을 구분했다. 팀 참여 삭제/정지·계정 정지/파기를 플래그와 무관한 DB 회수·감사/outbox에 연결한다. 프로젝트 참여 제거/검토자 전환은 해당 프로젝트의 허가만 회수한다. 이용권 회수는 웹 참여·구매 정원·AI 지급을 변경하지 않는다. 이미 서명된 오프라인 사본보다 이른 예정 회수는 소급 단축하지 않고 긴급 회수 대기로 처리한다.

장치는 개인키를 보내지 않고 Ed25519 공개키와 범위별 증명으로 등록한다. 발급은 실제 팀/프로젝트 제작 권한·해당 팀 배정을 재검사하고 120초 단회 확인 요청을 소비한다. 허가는 팀·프로젝트·장치·사용자·배정 버전에 고정하며 온라인 5분/오프라인 24시간과 E/예정 회수를 상한으로 서명한다. 중복 요청에는 허가 ID만 저장하고 원서명을 재구성하므로 만료를 늘리지 않는다. 계정 정지 후에도 자기 장치 키로 정확한 자기 허가를 반납할 수 있다. 종료 배정과 반납 허가는 DB에서도 되살릴 수 없다.
