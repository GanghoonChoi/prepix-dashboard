# Claude 병렬 작업 F 팀 복구 삭제 알림 운영 지원

PREPIX B2B v1.0 전체 구현의 작업 단위 12를 맡는다. F17 이용 종료와 복구, F19 알림, F20 운영 지원과 감사, S26/S27/S32/S33의 서버·대시보드·운영 콘솔과 로컬 종단 검증까지 구현한다. 사용자 요청에 따라 큰 병렬 작업으로 준비한 배정이며 앱 기준은 prepix(beta)다. 상태 표시나 삭제 대역만으로 전체 완료를 선언하지 않는다.

## 구현 범위

### 이용 종료 복구와 실제 삭제

- F17/P11의 정확한 E, E+30일, E+60일 경계를 기존 정책과 일치시킨다. E부터 30일 미만은 현재 자료 권한 안에서 열람/반출만, 30일부터 60일 미만은 복구 보관으로 미디어 접근 차단, 60일부터 삭제 경합을 검사한다. 자동결제 실패와 단건 종료를 같은 기준으로 처리한다. 알림 실패나 재시도는 E를 연장하지 않는다.
- 복구 건·삭제 작업·원주문·원래 E를 영속 연결하고 기존 팀 잠금을 사용한다. 삭제 시작, 복구 주문 시작, 실제 수납 적용, 미래 구매 기간 전환은 동일한 잠금 규칙을 통과해야 한다. 삭제 직전의 한 번 30분 보류를 재사용하고 새 요청/새로고침/새 주문으로 연장하지 않는다. 불명/수납 후 미적용/운영 확인 차단을 타임아웃이나 실패 조회만으로 해제하지 않는다.
- 삭제 작업에는 상태, 객체별 처리 목록, lease/heartbeat, 시도, 오류, 실제 삭제 시각을 기록한다. 팀 삭제 시작 후 신규 구매·복구·업로드·다운로드·공유·새 실행과 확정 경로에서 현재 삭제 상태를 검사한다. 만료된 작업자의 뒤늦은 확정이 파일이나 허용을 되살리지 않게 한다.
- 파일 원본/검토 파생본/AI 결과/직접 보관 자료/진행 중 multipart/기존 팀 보관함 등 실제 객체를 목록화한다. 현재 작업 분기에 없는 C/D의 새 객체는 명시적인 등록 인터페이스와 통합 검증 항목으로 인계한다. 같은 팀의 중복 객체는 한 번 삭제하고 다른 팀·개인 객체는 건드리지 않는다. 일부 삭제 실패를 전체 삭제 완료로 표시하지 않는다. 객체 저장소 오류·버전 객체·삭제 마커·보존 잠금의 동작을 사용하는 저장소와 맞춰 구현한다.
- 실제 객체 확인/삭제는 긴 DB 거래 밖에서 실행하고 확정은 현재 lease/상태/잠금으로 검사한다. 중단/재시작 시 남은 객체만 안전하게 처리한다. 자료 삭제와 감사/증빙 보존을 분리한다. 법정 보존 기간·운영 보존 약정은 미정 설정을 영구 보관이나 즉시 삭제로 해석하지 않는다.
- 복구 수납은 기존 적용 서비스에 연결한다. 새 기간/AI 지급 원장을 만들지 않는다. 삭제가 시작되거나 대상 E가 달라진 복구 적용은 기존 원주문으로 운영 확인한다. 실제 복구 가능 상태가 될 때 새 기간이 시작하고 종료된 참여자·만료 링크·기한 지난 휴지통은 자동 복구하지 않는다.

### 백업 파기와 복원 방지

- 실제 팀 자료 삭제 뒤 30일 이내 백업 제거 기한을 기록한다. 삭제 목록/tombstone은 복원된 DB와 객체에도 적용한다. 백업 사본의 제거 작업과 검증 결과를 기록하고 확인되지 않은 상태를 파기 완료로 표시하지 않는다.
- 백업 공급자/보관 구조가 확정되지 않았다면 어댑터 계약과 미설정 실행 차단을 구현하고 로컬 시험 백업을 대상으로 실제 제거·복원 시 삭제 목록 적용을 검증한다. 특정 클라우드의 모든 백업을 제거했다고 주장하지 않는다. 공급자별 구체 API를 구현할 때는 공식 문서로 확인한다.
- 삭제 목록과 고객 미디어의 보존 목적을 분리하고 운영 설정·적용 버전·대상별 결과를 남긴다. 오래된 백업을 복원한 뒤 삭제된 콘텐츠가 다시 다운로드 가능해지는 경로를 차단한다.

### 사용자 알림과 상태 갱신

- 기존 outbox의 확정 사건을 소비하고 사건+수신자에 하나의 알림을 만든다. 현재 역할/참여 회차/대상 접근으로 서버가 수신자를 계산한다. 검토 요청/승인 결정/요청 배정·제출/참여 변경/전송 실패/이용 종료/결제 결과를 구분한다. 단순 파일 등록을 검토 공개 알림으로 바꾸지 않는다.
- 수신 대상 확정, 실제 전달, 목록 표시, 클릭 시점에 현재 권한을 검사한다. 비참여 소유자/결제 담당자에게 비공개 프로젝트명·파일명·미리보기·수신 건수로 내용을 노출하지 않는다. 종료된 참여의 과거 알림을 새 참여 회차로 되살리지 않는다. 접근 소멸 시 일반 안내로 표시하거나 정책상 안전하게 숨기고 관련 시험을 남긴다.
- 본인 읽음/미읽음, 페이지 조회, 전달 시도와 실패 채널만 재시도를 구현한다. 알림 전달 실패가 제출·승인·수납을 되돌리지 않는다. 사건 처리 후 응답 유실/중복 소비/동시 작업자가 중복 알림을 만들지 않게 한다. 채널과 사전 안내 시점은 버전 있는 명시 설정이며 실제 메일 대신 로컬 포착함으로 인수한다.
- S27과 웹 알림 진입/미읽음을 연결한다. 계정·서비스·팀 전환과 지연 응답에서 이전 내용을 제거한다. 알림 클릭만으로 새 권한을 만들지 않는다. 재연결 시 현재 업무 상태를 다시 조회하고 놓친 알림을 작업 완료 상태로 추정하지 않는다.

### 운영 콘솔과 한정 지원

- S33 팀 운영 조회/사건·원주문·작업 대조/지원 건/담당자/다음 확인 기한/사유·종결 기록을 기존 콘솔에 추가한다. 콘솔 로그인·운영 조회·재처리·고객 콘텐츠 접근을 별도 권한으로 검사한다.
- 지원 건에는 문의/장애 식별자와 담당자·사유를 요구한다. 지원 허용은 특정 팀·프로젝트/파일·행동·종료 시각·승인 증거에 고정한다. 승인 주체와 허용 상한이 미정이면 해당 발급을 차단하는 명시 설정을 둔다. 범위 없는 전체 열람이나 운영자 자가 발급으로 무제한 콘텐츠 접근을 만들지 않는다.
- 현재 콘솔의 검증된 운영자 신원을 서버에서 신뢰 가능한 경로로 전달한다. 브라우저가 입력한 operator 문자열이나 공용 admin 키만으로 지원 권한을 만들지 않는다. 고객 JWT나 고객 계정을 대신 사용하지 않는다. 지원 허용을 일반 프로젝트 참여로 저장하지 않는다. 만료/회수된 허용은 기존 운영 세션의 새 콘텐츠 요청·주소 갱신에서도 거절한다.
- 수납 사업자 조회/기존 원주문 적용 재처리/실패 작업 재시도/삭제 보류와 해제는 원래 식별자·기대 상태·현재 운영 권한을 요구한다. 실제 수납 없이 주문을 성공 처리하거나 삭제된 자료를 복구 가능으로 바꾸지 않는다. 여러 번 재처리해도 기간·AI·파일·정산이 늘지 않는다. 결제 로직은 E의 도메인을 재구현하지 않고 기존 accessor와 작은 연결 커밋으로 제시한다.
- 중요한 B2B 조치와 감사/outbox는 같은 거래로 확정한다. 감사에는 실행자/대상/시각/전후 상태/사유/요청키를 남기고 일반 수정으로 덮어쓰지 않는다. JWT·비밀번호·카드 원문·빌링 키·서명 주소·고객 콘텐츠 본문을 감사/로그/인계에 넣지 않는다. 감사 실패 시 중요한 업무 변경도 실패해야 한다.
- S26/S32는 정확한 시각·현재 허용 행동·복구 진행/운영 확인·삭제 상태를 표시한다. 결제 권한 없는 참여자에게 결제 세부 정보를 숨긴다. 조회 실패를 삭제 완료/복구 가능/빈 목록으로 바꾸지 않는다. 응답 유실은 원키로 조회하며 계정/팀 전환 시 이전 응답을 표시하지 않는다.

## 병렬 경계와 통합

- Codex는 native 작업 파일·NAS·명시 전송/발행·납품 완료와 최종 통합, C는 검토본/검토/공유/승인, D는 팀 AI 실행과 앱/웹 S30, E는 구매/자동갱신/환불/명세를 맡는다. F는 위 작업 단위 12에 집중한다. 다른 세션의 작업 폴더를 수정하거나 커밋을 임의로 합치지 않는다.
- C/D/E의 새 사건과 객체가 필요한 연결에는 사건 envelope, 접근 검사 accessor, 정리 대상 등록 인터페이스를 문서화한다. 현재 주 코드에 있는 요청·파일·구매 사건부터 실제 연결하고 아직 없는 사건은 통합 계약과 명시적인 미검증 항목으로 인계한다. 이벤트명이나 새 표를 추측한 가짜 연결로 전체 완료를 선언하지 않는다.
- 공통 `contracts.ts`, 모듈/컨트롤러/작업자 등록, schema index, migration journal, 웹 생성 계약/내비게이션, 기존 주문 적용의 삭제 검사 변경은 `(integration)` 별도 커밋으로 나눈다. 0000~0063의 기존 migration은 수정/삭제하지 않는다. 자신의 0064 이후 번호는 다른 세션과 충돌할 수 있으므로 통합 담당이 빈 DB에서 의존 순서를 조정할 수 있게 인계한다.
- 정책·지원·백업·안내/보관 설정은 승인 버전과 누락 차단을 구현한다. 명세의 5분/24시간/30일/60일/한 번 30분/실제 삭제 뒤 백업 30일은 유지한다. 운영 확인 1영업일은 달력 설정과 담당자·기한 기록으로 처리하고 기한 경과만으로 자동 삭제를 재개하지 않는다.
- 자체 작업을 복구/삭제·백업 → 알림 → 지원/콘솔의 검증 가능한 단위로 나눠 커밋해도 된다. 전체 scope를 완료하려면 각 단위의 화면/서버/장애 인수를 마친다. 큰 작업을 하위 에이전트로 나누면 독립 폴더·파일 소유·공통 계약 담당자를 먼저 정한다.

## 필수 검증과 완료 기준

실제 PostgreSQL/Nest/JWT/엄격 DTO, 세션이 소유한 실제 MinIO, 실제 웹/콘솔 브라우저와 로컬 포착함/백업 사본을 사용한다. 대역과 실제 공급자 검증을 구분한다.

1. E/E+30/E+60 직전·정각·직후, 준비 팀 E 없음, 단건/자동 동일 접근, 유효한 다음 기간 전환을 확인한다. 현재 접근 정책을 UI와 서버가 함께 적용한다.
2. 복구 주문/수납 적용/삭제 claim을 동시에 실행해 양쪽 성공을 막는다. 30분 보류의 새로고침·새 주문 반복, 불명 수납·미적용·운영 확인, 이전 E와 현재 E 혼용을 검사한다. 원기간과 팀 잠금이 증거다.
3. 원본·파생본·보관함·multipart·중복 객체를 실제 삭제하고 중간 프로세스 종료/저장소 실패/lease 탈취 뒤 재시작한다. 남은 작업만 처리하고 다른 팀·개인 객체와 감사/증빙은 유지한다. 물리 객체 존재 확인을 완료 근거로 남긴다.
4. 로컬 백업에서 실제 제거 후 오래된 백업 복원을 재현한다. 삭제 목록 적용 전 자료 서비스를 열지 않으며 삭제된 자료의 조회/다운로드가 거절된다. 확인 불가 공급자 결과를 파기 완료로 표시하지 않는다.
5. 같은 사건 중복/동시 소비, 전달 후 저장 실패/응답 유실, 채널 실패 재시도, 읽음 타인 요청, 참여 회수/재초대/다른 팀과 계정 전환을 검사한다. 비공개 제목·검색·미읽음/건수·링크 클릭 누출이 없다. 단순 파일 등록은 검토 요청 알림이 아니다.
6. 운영 조회만으로 콘텐츠 주소를 발급할 수 없다. 지원 범위/행동/기한/회수·세션 재사용/다른 대상 치환을 검사한다. 감사 저장 실패가 변경을 취소하고 원주문 두 번 재처리가 지급을 늘리지 않는다. 삭제 보류/해제/실제 실행의 기록이 이어진다.
7. 서버 관련 회귀/타입/빌드, 웹·콘솔 타입/변경 lint/빌드와 실제 브라우저를 실행한다. 웹 390px 모바일, 지연 응답·응답 유실·새로고침, 현재 권한별 노출을 확인한다. 운영 인증은 명시적인 로컬 시험 경로로만 구성하고 실제 Google 계정이나 공용 키를 로그에 노출하지 않는다.

출발 서버 전체 검사에는 첫 197/197 통과 후 192/197 실패 기록이 있다. AI 원장 일부가 `B2B_TEAM_PREPARING`으로 실패했으며 같은 DB AI 단독 18/18은 통과했다. 시각 기준 차이는 조사 후보이고 해결된 것으로 계산하지 않는다. E에서 DB 시각 적용 변경 `d9cae02`를 작성한 흔적은 있지만 주 코드에 아직 통합/검증되지 않았다. 관련 변경이 필요하면 그 계약을 확인해 별도 통합 커밋으로 인계하고 시험 기간만 늘려 실패를 숨기지 않는다. 기존 서버 spec 타입 3건/웹 전체 lint 기준선도 상태 문서와 출발 재현을 함께 기록한다.
