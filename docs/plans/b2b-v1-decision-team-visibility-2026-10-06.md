# B2B v1 결정 변경: 팀 공개 범위·발행 즉시 검토 (2026-10-06)

서버 SOT: 백엔드 `backend/docs/b2b-team-visibility.md`(하나의 접근 판정, 호출자 목록, 저장, 검증). 이 문서는 제품 결정과 원 전달 문서(`PREPIX_B2B_개발전달문서_v1.0` 구조화 원본: `policies/functions/flows/ia/wires.json`) 대비 바뀐 항목을 기록한다. 원 전달 문서는 고치지 않는다.

## 유저 원문 (2026-10-06, 구속)

> 기본적인 B2B 팀 기능이 있고, 팀 워크스페이스의 공유 클라우드가 있어. 그리고 여기에 영상들 아카이빙이 가능해. 팀에 있는 개인 유저가 프로젝트 만들면, 영상을 publish하면 frame io나 드롭박스처럼 코멘트 달 수 있고 이걸 팀 내에서 다 공유 가능하게 하고, 그걸 유저가 웹에서 볼 수 있어야 하는게 핵심이야.

## 결정

1. **공개 범위 = 팀 전체 + 선택적 비공개.** 기본은 팀의 모든 현재 내부 멤버가 모든 프로젝트와 그 발행 영상을 보고 코멘트한다(Frame.io·Dropbox 팀 방식). 프로젝트 담당자가 **비공개**로 표시하면 v1 규칙 그대로다: 참여자만 보고, 소유자·관리자를 포함한 비참여자에게는 존재·제목·파일·코멘트를 숨긴다.
2. **발행 → 즉시 검토.** 발행한 결과의 검토본(미리보기 변환)이 준비되면 그 프로젝트를 볼 수 있는 모두가 웹에서 재생하고 코멘트한다. 검토를 "여는" 담당자 단계는 없다. 승인은 필요할 때만: 담당자가 승인자 1명을 지정한다(기존 단일 승인자 규칙 유지). 외부 공유 링크는 기존 규칙(기본 7일·범위·회수) 그대로 별도 명시 행동이다.

배경: 9월 설계 D14("팀 워크스페이스 = 팀의 영상 보관함, 팀 역할만으로 접근")를 10월 v1.0 명세가 참여자 전용으로 뒤집었다. 이번 결정은 팀 전체 모델을 되돌리고 그 위에 Frame.io식 검토를 얹는다. 원 정책 P01에도 "참여하지 않은 비공개 프로젝트"라는 표현이 있어, v1이 모든 프로젝트를 비공개로 구현한 것을 "팀 공개 기본 + 비공개 선택"으로 정리한 것이다.

| 소유자·관리자 | 팀 공개 프로젝트는 다른 멤버와 똑같이 봄. 비공개 프로젝트는 참여할 때만(P01이 비공개에만 적용) |

| 완료 관문(F16) | 변경 없음. 완료에는 최종 버전의 유효 승인이 여전히 필요 — 승인은 "필요할 때" 지정하지만 완료에는 필수 |
| 알림 | 명시 참여자에게는 지금처럼. 팀 홈에 볼 수 있는 것만으로 만든 "최근 발행" 섹션 → 팀 전체 알림 폭주 없이 발견 |

| 앱 재발행 계열 | 앱의 같은 작업 재발행은 현재 새 계열(새 검토)로 올라간다. 같은 검토에 회차로 쌓이려면 기존 자료의 새 버전으로 올려야 함 — 후속 후보 |

## 2026-10-07 보안 리뷰 반영 (위 표보다 우선)

10-06 표의 "외부 참여자 변경 없음", F12 "대상 = 프로젝트 전체", F14/S34 "프로젝트를 볼 수 있는 모두", "앱 재발행 계열" 행을 아래로 바꾼다.

- **외부 참여자 기본값.** 자동 발행은 내부 열람자·내부 참여자에게만 회차를 연다. 외부 참여자(고객)는 담당자가 **그 회차에 명시 선택**하거나 공유 링크를 보낼 때만 본다. 비공개 프로젝트도 같다(자동 발행은 내부 참여자에게만). 팀 열람자와 내부 코멘트는 담당자가 그 회차를 외부에 열지 않는 한 외부에 닿지 않는다. `review.requested` 알림도 같은 규칙을 따른다.
- **담당자가 외부에 여는 법.** 공개 범위 `project`에 `audienceUserIds`로 그 회차를 열 외부 참여자를 싣는다(웹: "프로젝트 내부 전체 공개" + "외부 참여자에게도 이 회차 공개 (선택)"). 같은 버전이어도 새 회차가 열린다. 외부 승인자는 목록에 있어야 한다. 대상 변경·버전 교체 양식은 현재 회차의 범위·대상·승인자로 시작한다 — `selected` 검토가 제출만으로 프로젝트 전체로 넓어지지 않는다.
- **회차별 공개.** 열람 판정은 회차마다다. 이전 `selected` 회차(코멘트·결정·재생)는 프로젝트 범위 회차가 새로 와도 그 회차의 대상에게만 남는다. 상세의 `rounds`에는 볼 수 있는 회차만 오고, 숨은 회차를 열면 404 `B2B_REVIEW_NOT_FOUND`.
- **재발행은 같은 검토에 쌓인다.** 앱은 같은 작업의 재발행에 `existingAssetId`를 보내 같은 자료 계열의 새 버전 → 다음 회차가 된다. 외부 제작자는 그 계열을 쓸 수 없으므로 새 계열(새 검토)로 올라간다.
- **같은 버전 재발행**이 이미 현재 회차면 회차를 새로 열지 않고 연결만 한다.
- **이전 버전은 자동 공개하지 않는다.** 같은 계열의 더 새 버전이 이미 검토 중이면 그 결과는 `automaticSkip: "superseded"`. 자동 발행 이전에 등록된 결과는 `"legacy"`로 일괄 공개하지 않는다. 둘 다 담당자가 "지금 공개"로 명시 공개할 수 있다.
- **자동 발행은 프로젝트 revision을 올리지 않는다** — 자동 공개가 다른 사람의 진행 중 편집을 충돌로 만들지 않는다.
