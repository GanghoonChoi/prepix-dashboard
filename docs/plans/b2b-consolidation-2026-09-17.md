# B2B 화면 통합 — 2026-09-17

발견된 문제 전부를 닫는 작업. 리포트가 아니라 실행 문서다. 각 항목은 검증 방법까지
같이 적는다.

## 1. 왜 이 문서가 존재하는가

B2B 기능을 훑으니 문제 대부분이 하나의 원인에서 나왔다: **조직(organization)과
워크스페이스(workspace)가 클라이언트에서 별개 모델로 구현돼 있는데, 서버에서는
1:1이다.** 그래서 멤버 화면이 두 개, 역할표가 두 개, 플랜 화면이 두 개다.

따라서 개별 증상을 하나씩 막는 대신 모델을 하나로 접는다.

## 2. 병합 방향과 근거 (백엔드 확인 완료)

`prepix-backend/backend/src` 를 읽어 확정했다.

| 사실 | 위치 |
|---|---|
| DB가 조직당 워크스페이스 1개를 강제 (`workspaces_one_per_organization`) | `organizations.service.ts:405` 주석 |
| 조직 초대는 `workspace_invitations` 에 org 컬럼을 채워 넣는 것 | `organizations.service.ts:390`, `invitations.service.ts:50` |
| 워크스페이스 초대 수락 시 `organizationMembers` 도 함께 생성 | `workspaces.service.ts:1033-1039` |
| 워크스페이스 역할 변경 시 `organizationMembers` 역할도 동기화 | `workspaces.service.ts:596-605` |

→ 두 화면은 **같은 사람, 같은 테이블**을 본다. 어느 쪽으로 합쳐도 데이터는 같다.

**결정: 워크스페이스 경로(`workspaceService`)를 남기고 조직 경로를 지운다.**

이유 — 워크스페이스 API만 가진 것들이 있고, 그 반대는 없다:
좌석 4분할(`seats`), 참여 정지/재개(`suspendedAt`), 제거 영향 미리보기(`impact`),
소유권 이전. 조직 API에는 이 필드가 아예 없어서 반대 방향 병합은 백엔드 작업이
선행돼야 한다.

잃는 것: 조직 초대 응답의 `hasAccount` (계정 없는 주소에 대한 안내 문구 뉘앙스).
→ 워크스페이스 초대도 상태별 문구가 있으므로 수용 가능한 손실.

### 2.1 이 결정이 드러낸 백엔드 버그 (선행 수정 필요)

워크스페이스 경로로 멤버를 제거하면 `workspaceMembers` 만 지우고
`organizationMembers` 행이 남는다 (`workspaces.service.ts:565-587`).
`leave` 도 동일 (`:1226`). 조직 경로의 제거는 두 테이블을 다 지운다
(`organizations.service.ts:296-320`).

멤버 제거를 워크스페이스 경로로 일원화하기 전에 이걸 고쳐야 한다. 안 그러면
"회사에 속하지 않은 사람이 조직 멤버로 남는" 상태가 만들어진다.

- **팀 삭제 없음.** `workspaceService` 에 delete 엔드포인트가 없다. 소유자는 소유권을

  변경한다.

## 6. 작업 중 새로 발견해 고친 것

계획에 없었지만 병합·검증 과정에서 드러났고, 전부 실제 사용자가 맞는 문제였다.

- [x] **N1. 행 메뉴가 스스로 닫혔다.** `RowMenu` 패널이 `position: fixed` 여서
      스크롤 시 닫도록 되어 있었는데, 리스너가 `capture: true` 라 문서 내 *모든*
      스크롤 컨테이너에서 발화했다. 멤버 표는 `overflow-x-auto` 로 감싸여 있고
      브라우저가 요소를 보이게 하려고 하는 스크롤도 여기 걸린다 → 메뉴에
      닿으려는 순간 사라졌다. 문서 좌표(`absolute`)로 배치해 행과 함께 움직이게
      하고 스크롤 닫기를 삭제. 아래로 공간이 없으면 위로 뒤집는다.
      · 검증: 하단 행의 케밥을 실제 브라우저에서 열어 위로 뒤집히는 것 확인
- [x] **N2. 모바일에서 페이지 전체가 가로로 스크롤됐다.** 멤버 표의 작업 열
      헤더에 있는 `sr-only` 라벨은 `position: absolute` 인데 위치 지정된 조상이
      없어 컨테이닝 블록이 문서였다. 즉 표의 `overflow-x-auto` 클립을 빠져나가,
      390px 화면에서 544px 표의 오른쪽 끝에 있던 1px 상자가 문서 스크롤 폭을
      520px 로 끌어냈다. `<th>` 에 `relative` 한 클래스로 해결.
      · 검증: e2e `scrollWidth <= innerWidth` 가 이제 실제로 이 회귀를 잡는다
- [x] **N3. 팀 기능이 꺼진 서버에서 출구가 없었다.** `/dashboard/workspaces` 가
      "사용할 수 없습니다" 한 줄만 띄우는데, 사이드바는 그 상태에서 스위처를
      숨기므로 클릭할 것이 아무것도 남지 않았다. 개인 계정으로 돌아가는 링크 추가.
- [x] **N4. 초대 어포던스 약화 방지.** 삭제한 조직 화면에는 표 헤더에 초대 버튼이
      있었는데 살아남은 화면은 접힌 `<details>` 뿐이었다. 표의 `onInvite` 를 연결.

### 운영 확인 (읽기 전용, 데이터 변경 없음)

- 삭제된 라우트가 실제로 사라짐 — `/dashboard/organizations/<uuid>/members`,
  `.../billing` 둘 다 404, `/dashboard/workspaces` 는 200. 이 라우트들은 이번
  배포 전까지 실제 페이지였으므로 새 빌드가 떴다는 직접 증거.
- 라이브 페이지가 로드한 스크립트 17개(832KB)를 브라우저에서 그대로 읽어 대조:
  - 대조군(바뀌지 않은 i18n 값)이 존재 → 검사 자체가 유효함을 먼저 확인
  - 신규 문구 **7/7 존재** (`소유권 이전 · 관리자 지정`, `관리자 제외`,
    `역할별 권한`, `관리자는 누구도 소유자로 지정할 수 없습니다` 등)
  - 삭제 문구 **8/8 부재** (`결제 담당자`, `결제·좌석·소유권 이전·팀 삭제`,
    `비어 있을 수 없습니다` 등)
- 로그인 화면 정상 렌더, 404 화면도 앱의 404(복귀 버튼 포함)로 동작.

배포됐는가"를 확인하는 것이 남은 유일한 미지수였다.
