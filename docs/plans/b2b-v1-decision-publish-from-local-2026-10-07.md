# B2B v1 결정 — 로컬 작업을 팀 폴더에 발행한다 (2026-10-07, 레인 P)

**이 결정은 "팀 프로젝트를 앱에서 열어 함께 편집한다"(F12 팀 작업 사본, 앱 `TeamProjectOpen`)를 핵심 흐름에서 뺀다.** 요청·납품·완료는 제품에 남는다.

## 유저 말 (구속)

- "팀 프로젝트를 공유하는게 아니라, 팀에 속한 개인이 로컬에서 작업하던 그 영상을 Publish하면 팀이 그 작업을 공유받을 수 있는거야."
- 앞서: "B2B 워크스페이스로서, 클로드처럼 개인 및 팀멤버 사용량이 각각 있고, 팀에는 공용 클라우드가 있어서 유저가 모두 사용 가능함. 그리고 팀 멤버가 만든 영상을 웹에 공유하여 코멘트를 남길 수 있게 함."

## 유저의 세 답

1. **작업 맥락 = 앱에서 고른 워크스페이스(클로드처럼).** 팀 A를 고른 채 만든 로컬 프로젝트는 팀 A의 것이다. 그 AI는 "팀 A 안의 내 몫"(레인 K의 사람별 팀 미터, `x-prepix-ai-scope: team:<id>`)으로, 발행은 팀 A로 간다. 개인 공간에서 만든 프로젝트는 개인 사용량이고, 팀 발행은 팀 맥락의 작업에서만 나온다.
2. **묶음은 폴더.** 팀 클라우드에는 폴더(예: 고객사별)가 있다. 발행할 때 폴더를 고르고, 안 고르면 "기본" 폴더로 간다. 같은 로컬 작업을 다시 발행하면 같은 항목의 다음 버전(회차)이 되고, 이전 코멘트는 그 버전에 남는다.
3. **팀원은 웹에서 보고, 코멘트하고, 받는다.** 편집은 발행한 사람만, 자기 앱에서 한다. 팀원은 남의 작업을 앱에서 열지 않는다.

## 대응 (새 표 없음, migration 없음)

| 제품 말 | 서버 기록 |
| --- | --- |
| 폴더 | 기존 팀 프로젝트(`b2b_projects`) — 팀 공개/비공개, 검토, 발행, 파일 그대로 |
| "기본" 폴더 | 팀마다 하나, 필요할 때 만든다. id는 팀에서 유도(v3 이름 UUID) → 동시에 처음 발행해도 한 줄. 첫 호출자가 담당자, 팀 공개 |
| 항목 | 폴더 안의 검토 하나(업로드 자산 계열). 같은 로컬 작업(`originWorkId`)의 재발행은 V의 계열 쌓기로 다음 회차 |
| 폴더 만들기 | 모든 내부 멤버(기존 프로젝트 만들기) |

- 서버: `RegisterPublication`의 `participationId`·`basisRevision`을 **둘 다 생략**하면 로컬 작업 등록(작업 사본이 없으니 기준 충돌 없음, 내부 멤버만). 둘 다 보내는 작업 사본 경로는 그대로. `POST …/b2b/projects/default-folder`(만들거나 가져오기). 검토 목록 `ReviewSummary`에 `publisher`·`commentCount`. SOT 백엔드 `backend/docs/b2b-publish-from-local.md`.
- **2026-10-07 메인 기본값 추가**: 외부 공유 링크(만들기·목록·링크·회수)는 담당자 **또는 그 항목을 발행한 사람**(자기 항목만). 다른 멤버 항목은 403, 담당자는 전부 관리.

## 웹

- 팀 화면의 "프로젝트"를 "폴더"로(홈·목록·만들기·설정·비공개 선택). 경로·API·코드 식별자는 그대로.
- 폴더 페이지는 **발행된 항목**이 맨 앞: 제목, 발행자, 최신 버전(v), 날짜, 코멘트 수 → 각 항목은 검토 페이지(재생·코멘트·이 버전 받기)로.
- 팀 홈 "최근 발행" 유지.
- 요청·납품·완료는 폴더 안에 남기되 항목 아래 "요청·납품·완료"(접힌 "더 보기")로 낮췄다. 지우지 않았다.
- 검토 페이지: "이 버전 받기" 추가(파일 받기 API가 허락할 때만), 발행자에게도 "공유" 구역.
- 폴더 페이지의 "앱에서 작업하기"(`prepix://team-project`)는 숨김(`APP_ENTRY = false`, ponytail — 병합 뒤 삭제).

## 앱

- 로컬 프로젝트가 만든 때의 팀을 기억한다(`projects.team_space`, 한 번 정하면 고정, 기존 행은 개인). 팀 화면에 "이 팀의 내 작업" 목록·새 프로젝트·"웹에서 팀 보기".
- AI 범위는 한 해석기(`aiScopeForProject`)에서 팀 맥락을 읽는다. 기존 팀 작업 사본도 그대로 자기 팀.
- 팀 맥락 편집은 그 팀의 내 좌석이 필요(P04, `GET licences/mine`). 없으면 "이 팀에서 편집하려면 좌석이 필요합니다" + 웹 링크. 발행 자체는 좌석을 따로 요구하지 않는다(업로드는 서버의 기존 제작자 규칙).
- 내보내기 창의 "팀에 발행": 폴더 고르기(기본값 "기본", 그 자리에서 새 폴더), 제목 기본값은 로컬 프로젝트 이름, 같은 작업의 재발행은 지난번 폴더가 기본값. 발행 뒤 웹 검토 링크(복사·열기)와 "팀 밖 공유는 웹 검토 페이지에서" 안내.
- 숨김: 링크로 남의 팀 프로젝트를 앱에서 여는 길(`TeamProjectOpen`의 작업 사본 열기, ponytail). 기존 작업 사본은 라이브러리에서 열고 발행할 수 있다.

## 열린 것

- "기본" 폴더를 담당자가 비공개로 바꾸거나 완료·보관하면 그 폴더로의 기본 발행은 실패한다(다른 폴더를 고르면 된다). 이름이 "기본"인 다른 폴더를 사람이 만들면 앱 선택기에서 가려진다.
- 팀 맥락 편집의 좌석 확인은 화면 관문이다(같은 파일은 개인 공간에서 자유롭게 편집된다). 오프라인은 마지막 답을 유지한다. 실제 집행은 서버의 팀 AI 좌석 확인.
- 팀의 로컬 작업 목록은 이 컴퓨터의 최근 50개 로컬 프로젝트에서 거른다.
