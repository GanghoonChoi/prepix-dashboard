## 개발 순서와 완료 기준

각 단계는 서버 계약, 연결 화면, 장애 복구와 인수 검증까지 포함한다. 개인 프로젝트의 오프라인 편집과 개인 결제는 유지하며 팀 프로젝트의 유료 권한과 사용량을 별도로 처리한다. 가격이 미정인 동안에는 명시적인 테스트 상품을 사용한다.

| 순서 | 개발 묶음 | 주 작업 영역 | 완료 기준 |
| --- | --- | --- | --- |
| 0 | 전환·상품·기술 설정 계약 | 상품·기술 책임자, 서버 | 기존 보관함 공개 범위와 보존 약정, 최소 앱 버전, 지원 파일·장치·AI 단위와 미정 설정의 차단 조건을 기록한다. |
| 1 | 보관함과 파일 수명 | 서버·웹·저장 작업자 | 마지막 연결 제외 후 담당자가 허용된 정확한 버전을 찾아 재연결할 수 있다. 비공개 사용 위치를 숨기고 자료 인계·휴지통·증거 보호를 처리한다. |
| 2 | beta 앱의 파일·발행·NAS | 앱 중심, 서버·웹 연결 | 실제 팀 허가와 OS 키 저장을 검증한다. 재시작 뒤 남은 조각만 전송하고 특정 버전을 검증 수령한다. 저장·전송·검토 공개를 구분하며 원본 연결의 내용 일치를 확인한다. |

개발 의존성은 파일 접근/버전 → 실제 AI 입력과 발행 → 검토/제출 → 납품 완료/증거 보호다. PG 계약·결제 화면과 운영 설정 준비는 이 흐름과 독립적으로 진행할 수 있다. 출시 전에 구매와 실제 삭제 운영까지 인수를 통과해야 한다. 인원과 운영 환경이 확정되기 전에는 단계 번호를 출시 날짜로 환산하지 않는다.

## 첫 개발 묶음인 보관함

보관함의 현재 조회·검색·종류 필터와 정확한 버전의 다운로드/재연결을 연결했다. 마지막 계열 참조 제외 뒤 자료 담당자의 기존 허용을 유지하되 현재 내부 팀 참여·제작 참여·자료 허용·선택 버전의 실제 과거 참조를 함께 검사한다. 다른 참여자의 파생 허용과 퇴사/프로젝트 제거 뒤의 허용은 유지하지 않는다. 0055는 기존 자료에서 증명 가능한 마지막 연결 제외 허용만 감사와 함께 복구한다. 다음 작업은 보관함 직접 등록, 담당자 이전/객관적 복구와 휴지통·증거 보호다.

1. 프로젝트 참조 권한과 연결 제외 뒤의 보관 접근을 명시한다. 자료 담당자 ID만으로 조회를 우회하지 않고 현재 팀 참여·자료 접근의 근거와 회수 이력을 검사한다. 퇴사·정지·프로젝트 제거 뒤 재초대해도 이전 허용을 되살리지 않는다.
2. S10 목록·검색·종류 필터와 S11 정확한 버전·상세를 연결한다. 사용 위치는 현재 접근 가능한 프로젝트만 표시한다. 보관함 직접 등록도 담당자·초기 공개 범위·용량 예약을 같은 계약으로 처리한다.
3. 정확한 버전을 다른 프로젝트에 재연결한다. 물리 바이트를 복사하거나 원프로젝트의 다른 사용자 허용을 자동 복사하지 않는다. 응답을 잃으면 원래 요청 키와 입력으로 결과를 확인한다.
4. 자료 담당자 이전과 객관적으로 담당자가 사용할 수 없는 경우의 복구를 연결한다. 소유자에게 정상 담당자의 자료를 볼 수 있는 일반 우회 권한을 주지 않는다.
5. 휴지통·복구·영구 삭제와 참조 보호를 연결한다. 요청·승인·완료 증거와 연결된 삭제 제한은 협업 도메인이 준비된 뒤 실제 증거를 사용해 검증한다.

이 묶음의 인수는 마지막 연결 제외→보관함 검색→같은 버전 다운로드/재연결, 다른 사용자 정보 비공개, 비참여 관리자 차단, 팀/프로젝트 제거 뒤 재초대, 같은 팀 중복 용량 유지, 재연결 응답 유실 복구다. 휴지통은 계속 용량에 포함하고 30일과 팀 삭제 일정 중 빠른 마감을 표시한다.

## beta 앱 파일과 팀 AI 연결

앱의 [기존 업로드](/Users/spagettimaker/My/Lasker/prepix/apps/desktop/src/main/services/workspaces/upload.ts:176)는 실행 중 Map에 상태를 두고 새 파일 ID로 첫 조각부터 보낸다. 이를 영속 전송 기록으로 확장하고 새 B2B 프로젝트 API의 완료 조각과 대조한다. 기존 [검증 다운로드](/Users/spagettimaker/My/Lasker/prepix/apps/desktop/src/main/services/workspaces/download.ts)는 해시 확인과 원자적 완성 기반을 재사용하되 프로젝트·버전·현재 계정에 고정하고 중단 후 수령 재개를 추가한다.

native 작업 파일은 검증된 형식과 지원 크기를 먼저 승인한다. 실제 악성 파일 검사 엔진과 최신 검사 데이터, 검토본 변환을 운영 환경에서 확인한다. 변환 실패와 원본 저장 실패는 별도 상태로 처리하며, 검토본 재생 권한으로 원본 주소를 제공하지 않는다. NAS의 실제 경로는 장치에 보관하고 빠른 fingerprint는 후보 탐색에 사용한다. 이름과 크기만으로 원본 일치를 확정하지 않는다.

팀 AI는 [정산 서비스](/Users/spagettimaker/My/Lasker/prepix-backend/backend/src/b2b/ai-accounting.service.ts)를 재사용한다. 현재 [AI HTTP 계약](/Users/spagettimaker/My/Lasker/prepix-backend/backend/src/b2b/ai.controller.ts)은 사용량·조회·취소이므로 입력 접근과 가격이 검증된 견적/접수 API를 먼저 추가한다. 공급자 실행 식별자와 실제 결과 버전을 정산 영수증에 연결한 다음 앱의 분석·STT·에이전트와 웹 S30을 연결한다. 현재 앱의 [팀 AI 차단](/Users/spagettimaker/My/Lasker/prepix/apps/desktop/src/main/services/b2b/ai-route.ts)은 개인 과금 경로로 팀 입력이 흘러가지 않게 하는 임시 제한이며 실제 팀 실행 연결 뒤에 교체한다.

인수에는 실제 HTTP/OS 키 저장소의 재시작·절전, 앱 종료/재시작 전송, 내용이 바뀐 NAS, 두 팀과 개인 과금 분리, 같은 작업의 응답 유실·재실행 대조, 동시 예약·취소·24시간 종료와 과거 기간 정산을 포함한다. 만료한 작업의 결과를 자동 게시하거나 새 기간 사용량으로 이동하지 않는다.

## 협업과 출시 운영

요청에는 당시 확인 기준과 자료 버전을 보존한다. 기준·형식·제출물이 바뀌면 재확인하며 담당자나 기한 변경만으로 기존 확인을 무효화하지 않는다. 검토 코멘트와 한 명의 지정 승인자의 승인은 영상 버전에 고정한다. 새 영상에 과거 승인을 승계하지 않는다. 납품 완료는 최종 영상 승인, 필수 요청 확인/명시적 면제, 필요한 작업 파일의 실제 열기 확인을 한 시점에 검사하고 당시 근거를 보존한다. 재개·보관·보관 해제를 별도 행동으로 구현한다.

구매는 [수납 대조](/Users/spagettimaker/My/Lasker/prepix-backend/backend/src/b2b/payment-reconciliation.service.ts)와 [기간 적용](/Users/spagettimaker/My/Lasker/prepix-backend/backend/src/b2b/entitlement-application.service.ts)을 재사용한다. 현재 `checkoutReady`는 false다. 결제 수단 등록, 자동갱신, 웹훅, 환불 실행과 증빙 화면을 연결하고 실제 PG 시험 환경에서 중복·역순·수납 후 반영 실패를 확인한다. 추가 구매의 일할 조건과 원주문/구매자 사본을 유지한다.

팀 종료 E 이상 E+30일 미만은 현재 권한 안에서 열람·반출만 허용한다. E+30일 이상 E+60일 미만은 복구 보관이며 미디어 열람을 막는다. E+60일부터 실제 삭제와 복구 시작을 같은 팀 잠금으로 통제한다. 삭제 직전 30분 보류는 한 번만 사용하고 불명 수납은 삭제를 멈춰 운영 확인에 연결한다. 실제 삭제 뒤 백업은 30일 이내 제거하고 백업 복원에도 삭제 목록을 적용한다.

알림은 감사/outbox에서 생성하되 조회와 이동 시 현재 접근을 검사한다. 운영 콘솔에는 콘텐츠 권한과 구분된 지원 건·사유·기한·승인 범위를 추가한다. 원주문 재처리, 원장 불일치, 삭제 보류와 지원 종료를 담당자가 처리할 수 있어야 한다.
