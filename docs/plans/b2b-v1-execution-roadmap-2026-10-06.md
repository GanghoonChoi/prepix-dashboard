## 개발 순서와 완료 기준

각 묶음은 서버 동작·연결 화면·인수 검증까지 끝낸다. 서버 기반이나 화면의 존재만으로 기능 전체를 완료 처리하지 않는다. 개인 프로젝트의 오프라인 편집과 개인 결제는 계속 지원한다.

| 순서 | 작업 묶음 | 주 작업 영역 | 완료 기준 |
| --- | --- | --- | --- |
| 1 | 실제 팀 프로젝트와 앱 편집 연결 — F06·F11·S28 | 앱 중심, 웹·서버 연결 | 서버 확인을 거친 사용자·팀·프로젝트·서비스를 로컬 파일과 목록에 고정한다. 링크·계정 전환·파일 이동·재등록·저장으로 소속이 바뀌지 않는다. 만료 뒤 새 편집은 막고 이미 반영된 작업의 열람·저장은 유지한다. |
| 2 | 팀 AI 예약과 정산 — F07·S30 | 서버 중심, 앱 실행 입구·웹 사용량 | 현재 프로젝트 권한과 해당 팀 이용권을 검사한 뒤 원래 지급 건·기간에 예약한다. 동시 실행에도 팀 잔액·개인 한도가 음수가 되지 않고 개인 사용량을 대신 차감하지 않는다. |
| 3 | 구매와 갱신 및 원결제 정산 — F18·S21~S24 | 서버·웹, PG 연동 | 구매 확인→수납→이용권 반영을 구분한다. 응답 유실·중복 웹훅·자동/단건 경합·환불 재시도에도 원주문 하나의 결과만 반영한다. 실제 판매는 P17 설정과 결제 검증 뒤에 연다. |
| 4 | 파일 버전과 전송 및 발행 — F08~F12·S08~S11·S29·S31 | 서버·저장 작업자·앱·웹 | 같은 팀 물리 객체의 여러 프로젝트 참조를 중복 과금하지 않는다. 검토본 재생과 원본 다운로드 권한을 분리한다. 앱 재시작 뒤 같은 전송·버전의 남은 조각만 보내고, 발행 시 현재 권한을 재검사한다. |
| 5 | 요청과 검토 및 납품 — F13~F16·S12~S17·S34 | 서버·웹, 앱 발행 연결 | 코멘트와 승인을 특정 영상 버전에 고정한다. 제출과 확인을 나누고 기준 변경 시 재확인한다. 유효한 최종 승인·필수 요청 확인/면제·필요한 작업 파일 열기 확인이 있어야 완료 사본을 만든다. |
| 6 | 복구와 삭제 및 운영 — F17·F19·F20·S25~S27·S32·S33 | 서버·작업자·웹·콘솔 | 복구와 삭제가 동시에 성공하지 않는다. E·E+30일·E+60일에서 모든 클라이언트의 권한이 일치한다. 알림은 현재 접근권한을 검사하고, 명세 정정·지원 기한·실제 삭제와 백업 파기를 기록한다. |

팀 AI의 정산 틀은 2번에서 완성하고 입력 파일 버전 연결은 4번과 함께 마무리한다. 결제 수단·검토본 변환 환경·콘솔 화면 준비는 선행 계약 확정 후 별도로 진행할 수 있지만, 각 기능 공개는 표의 완료 기준을 따른다.

### 다음 앱 연결 묶음

1. 팀 연결 정보를 파일과 로컬 목록에 함께 보관한다. 잘못된 정보나 두 기록의 충돌은 개인 프로젝트로 처리하지 않는다. 기존 로컬 개인 파일은 팀 인증 없이 연다.
2. 기존 `prepix://open?workspace=…` 링크를 유지하며 서버 프로젝트를 지정하는 새 링크를 웹 생성기·앱 parser·저장 상태·IPC에 함께 추가한다. 버전을 지정한 링크는 그 버전을 실제로 열 수 있을 때 지원한다.
3. 편집 큐뿐 아니라 이름·설정·자료 가져오기·에이전트·발행 등 변경 입구를 점검한다. 로컬 화면 이동·재생·이미 반영된 작업 저장은 새 편집과 구분한다. 만료 안내와 재확인 동작을 화면에 연결한다.
4. 팀 AI 정산 연결 전에는 팀 프로젝트가 기존 개인 예약이나 개인 에이전트 과금 경로로 실행되지 않도록 막는다. 편집 허가를 서버 AI 권한으로 사용하지 않는다.
5. 서버 HTTP 연결과 실제 Electron 키 보관으로 앱 재시작·절전·OS 재부팅·계정 전환·장치 회수를 확인한다. Windows·macOS의 실제 실행을 완료 기준에 포함한다.

현재 [링크 parser](/Users/spagettimaker/My/Lasker/prepix/apps/desktop/src/main/services/deeplink/parse.ts)는 `project` 쿼리를 거절한다. [업로드 서비스](/Users/spagettimaker/My/Lasker/prepix/apps/desktop/src/main/services/workspaces/upload.ts)는 실행 중 전송을 메모리 Map에 보관한다. [AI 예약 입구](/Users/spagettimaker/My/Lasker/prepix/apps/desktop/src/main/services/media/media-analysis/quota.ts)는 사용자·개인 기간을 기준으로 동작한다. 이 세 경로의 변경이 앱 연결·전송 재개·팀 AI의 실제 구현 대상이다.

## 인수 검증

- 개인 유료 계정이 두 팀에 참여해도 콘텐츠와 과금이 섞이지 않아야 한다. 미참여 소유자·관리자의 직접 주소 접근에서 제목·파일 주소·검색 건수가 노출되지 않아야 한다.
- 남은 정원 하나의 동시 배정, 여러 오프라인 장치의 회수, 기간 경계의 AI 예약·정산을 확인한다. 회수 대기가 끝나기 전에 정원을 재사용하지 않는다.
- 앱 종료 후 전송 재개, NAS 원본 변경, 검토본 변환 실패, 새 영상 버전과 과거 승인, 작업 파일 누락을 재현한다.
- 중복·역순 수납 통지와 수납 후 반영 장애를 원주문으로 재처리한다. 복구 구매와 삭제를 동시에 실행해 양쪽 성공을 막는다.
- 제한된 운영 계정의 콘텐츠 접근 차단, 지원 기한 종료, 인보이스 정정 사본과 과거 사업자 정보, 백업 파기 기록을 확인한다.

이번 실행 계획 정리에서는 웹과 앱의 B2B 생성 계약이 서버 계약과 일치함을 확인했다. 기존 검사 결과는 구현 상태 문서에 기록된 각 작업의 결과다. 미완성 앱 연결 코드에 그 결과를 적용하거나, 이 계획 작성으로 전체 구현·운영 검증이 완료됐다고 표시하지 않는다.
