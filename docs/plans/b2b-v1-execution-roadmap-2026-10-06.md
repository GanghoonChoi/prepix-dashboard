## 개발 순서와 완료 기준

각 묶음은 서버 동작·연결 화면·인수 검증까지 끝낸다. 서버 기반이나 화면의 존재만으로 기능 전체를 완료 처리하지 않는다. 개인 프로젝트의 오프라인 편집과 개인 결제는 계속 지원한다.

| 순서 | 작업 묶음 | 주 작업 영역 | 완료 기준 |
| --- | --- | --- | --- |
| 1 | 실제 팀 프로젝트와 앱 편집 연결 — F06·F11·S28 | 앱 중심, 웹·서버 연결 | 서버 확인을 거친 사용자·팀·프로젝트·서비스를 로컬 파일과 목록에 고정한다. 링크·계정 전환·파일 이동·재등록·저장으로 소속이 바뀌지 않는다. 만료 뒤 새 편집은 막고 이미 반영된 작업의 열람·저장은 유지한다. |

### 앱 연결의 현재 상태와 남은 인수

서버 프로젝트를 확인해 서비스·사용자·팀·프로젝트를 파일과 로컬 목록에 고정한다. 웹의 앱 링크와 앱 열기·재시도·계정 변경 처리를 연결했고, 파일 이동·재등록·저장·되돌리기로 소속을 바꿀 수 없도록 검사한다. 개인 로컬 프로젝트는 팀 인증 없이 오프라인에서 연다. 처음 여는 팀 프로젝트는 빈 로컬 작업 사본을 만들며 클라우드 최신 파일 다운로드는 4번 묶음에서 연결한다.

실제 편집 큐·이름/설정·자료 변경 입구와 화면의 편집 상태를 연결했다. 만료 뒤 새 편집은 막고 기존 시퀀스 선택·재생·이미 반영된 작업 저장은 허용한다. 서버 재확인은 4분마다 수행하며 수동 재확인도 서버를 호출한다. 네트워크 실패 때는 원래 서명된 오프라인 만료 시각까지만 허용한다. 버전을 지정한 링크는 지원 안내를 표시하고 의도를 보존한다.

팀 AI 정산 연결 전에는 팀 입력이 개인 예약·에이전트와 로컬 STT로 실행되지 않도록 검사한다. 실제 F07 예약·정산으로 교체할 임시 제한이다. 프로젝트 조회와 장치 허가 발급의 실제 HTTP, 실제 Electron OS 키 저장소의 재시작, 절전·OS 재부팅·Windows/macOS 실행을 추가 검증한다. 발행 권한과 NAS 원본 재연결은 파일 버전 묶음에서 다룬다.

| 미디어와 AI | 지원 형식·크기, 변환 규격, 저장량 산정, 작업별 최대량, 장치 정책 | 입력 검사·예약 상한·저장 작업자 설정에 반영한다. |
| 기존 팀 전환 | 기존 공유 보관함 공개 범위, 파일 보존 약정, 신규 프로젝트 연결, 최소 앱 버전 | 객체를 보존하는 추가형 전환과 재실행 가능한 backfill을 사용한다. |
| 운영 | 지원 접근의 범위·사유·기한, 로그·개인정보 보관, 실제 삭제와 백업 파기 | 콘솔과 작업자 계약 및 운영 인수 기록에 반영한다. |

상품·기술·재무/법무·보안 검토 항목은 전달 문서 P17에 따른다. 특정 출시 날짜는 담당 인원, 미디어 실행 환경, 결제 계약과 기존 데이터 전환 범위가 정해진 뒤 산정한다.

## 인수 검증

- 개인 유료 계정이 두 팀에 참여해도 콘텐츠와 과금이 섞이지 않아야 한다. 미참여 소유자·관리자의 직접 주소 접근에서 제목·파일 주소·검색 건수가 노출되지 않아야 한다.
- 남은 정원 하나의 동시 배정, 여러 오프라인 장치의 회수, 기간 경계의 AI 예약·정산을 확인한다. 회수 대기가 끝나기 전에 정원을 재사용하지 않는다.
- 앱 종료 후 전송 재개, NAS 원본 변경, 검토본 변환 실패, 새 영상 버전과 과거 승인, 작업 파일 누락을 재현한다.
- 중복·역순 수납 통지와 수납 후 반영 장애를 원주문으로 재처리한다. 복구 구매와 삭제를 동시에 실행해 양쪽 성공을 막는다.
- 제한된 운영 계정의 콘텐츠 접근 차단, 지원 기한 종료, 인보이스 정정 사본과 과거 사업자 정보, 백업 파기 기록을 확인한다.

10월 6일 앱 연결 검사 353개·새 빌드의 실제 Electron 화면 검사 1개·앱 타입 검사 6단계와 변경 lint가 통과했다. 화면 검사에는 서버/OS 암호화 테스트 대역을 사용했다. 웹의 단위 검사 91개·타입·변경 lint·빌드, 웹/앱의 서버 계약 동기화도 통과했다. 실제 HTTP/OS 환경·팀 AI·클라우드 파일·결제와 운영 인수는 각 묶음의 남은 완료 기준이다.

팀 AI 서버 기반은 B2B 106개·기존 회귀 159개·빈 DB 마이그레이션 54개·실제 Nest/JWT/DTO 조회/취소 HTTP 검사를 통과했다. 입력 버전과 공급자 결과는 합성 자료를 사용했으므로 실제 파일·견적·실행·앱 인수는 다음 완료 기준으로 남는다. 전체 백엔드 테스트 타입 오류 3건은 기존 기준선이다.

팀 AI 사용량과 본인 작업 내역/취소 연결은 B2B 108개·웹 단위 92개·실제 Nest/JWT/DTO HTTP·실제 서버 브라우저 1개·웹 타입/lint/빌드·앱 타입 6단계·계약 동기화를 통과했다. 브라우저에서 데스크톱/모바일·취소 응답 유실·같은 요청 재확인·참여 제거 후 제목/내역 제거를 확인했다. 대조 실패의 웹 표시는 응답 대역을 사용했고 실제 DB 불일치 차단은 PostgreSQL 검사에서 확인했다. 실제 입력·견적·공급자 실행·beta 앱 S30 인수는 남는다.
